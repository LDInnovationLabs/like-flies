1. Imported crumb could not be found by the importer

Each crumb now keeps two separate identities. by is the original hider, who can never find it. own is the manager (the importer, for an imported crumb), who alone can replace or delete it. A find is rejected only when pid === c.by, when the player has already found it, or when there are 16 finds. Search is refused only for the original hider. The card shows "imported by you" to the importer.

2. Snapshot sender authority

actOnSnap(j,d) now:

  1. validates the entire structure, with bounds, before anything else touches it: members, passes, IT, separation list, timers, names, crumbs and finds
  2. rejects a snapshot whose stated coordinator d.hs is not the sending connection j
  3. holds (does not apply) a snapshot from a connection that is not the current coordinator. A held snapshot is applied only if that sender actually becomes the coordinator within 8 s, which preserves handoff when the snapshot arrives before the peer list catches up.

Only after these checks does the epoch/revision comparison run. The coordinator re-sends its snapshot every 3 s, so late joiners still catch up.

This pass also fixed a crash present in v0.0.19: the first activity change threw "Cannot read properties of undefined (reading 'it')" because lastSeen started as {}.

3. Buzz Tag fast fly-by

What changed

  • Sweeps: contact is swept over the time interval both flies' samples actually cover. Each IT/runner pair continues from where its previous sweep ended, so a crossing that falls between two coarse samples is no longer skipped.
  • Timestamps: remote samples are time-stamped by the sender with a real-time clock (performance.now).
  • Receive-age correction: the receiver estimates each sample's age from the drift against a sliding 3 s minimum offset, plus half the measured round trip. The coordinator pings every 2 s once 2 or more players are in Tag. Base latency is capped at 0.15 s and total age at 0.3 s.
  • Unchanged: stale-data age (0.5 s), reach (0.55 × fly size), wall occlusion, the teleport/span guard, the 2 s ready / 4 s protection, and the no-repeat separation rule.

LIVE fast-pass result

The one allowed two-peer check (under 3 minutes) FAILED. It ran before the real-time timestamp change, while samples were still stamped with each page's game clock. Software rendering ran those clocks at different speeds, so the samples looked stale and RTT read 0. The scripted crossing also took about 7.5 s, so it was not a fast pass.

A follow-up diagnostic after the fix (not a pass/fail test) showed a live held contact tagging normally (distance 0, reach 0.275, RTT about 0.49 s).

Honest limit: a fast live fly-by has not been verified in this environment. On real headsets, compensation needs one round-trip ping first (up to 2 s after the second player joins). Delays beyond about 150 ms base latency still under-correct crossing paths.
